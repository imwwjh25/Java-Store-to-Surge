# 先说结论

? **修改同一行是最常见的冲突原因，但不是唯一原因！**
Git 冲突本质：**Git 在合并两个分支时，发现同一个文件的同一块区域，两边都做了不一样的修改，Git 不知道该保留哪一份，就交给人来判断**。

>
> Git 是按「代码块（hunk）」对比，不是严格只按单行。

## 1. 典型场景：同一行被两个人改了（最常见）

文件 `Test.java`
分支 A（你）：

```
// 原来：String name = "张三";
String name = "张三同学";
```

分支 B（同事）：

```
// 原来：String name = "张三";
String name = "小张三";
```

合并的时候，同一行两处修改，Git 无法自动合并 → 冲突。

## 2. 不是同一行，也会冲突！（很多人不知道）

Git 的对比是**连续的代码块**。
举例子：
原始代码：

```
void hello(){
    System.out.println("hi");
}
```

- 你：在 `println` 上面加一行代码
- 同事：修改 `println` 这一行
  这两块属于**相邻的同一个 hunk**，Git 也会判定冲突。

还有一种：

- 你删除了一整块函数
- 同事在这个函数里面新增代码
  哪怕你们修改的不是同一行，合并照样冲突。

>
> 简单理解：Git 看的是「上下文连续区域」，不是单行。

## 3. 还有别的冲突类型

1. **文件删除冲突**：你删了这个文件，同事在这个文件里新增代码
2. **文件名冲突**：一边改名，另一边修改原文件
3. **目录冲突**：一边把文件移动到 A 文件夹，另一边移动到 B 文件夹

## 4. 没有冲突的情况（对比理解）

- 两个人修改**同一个文件，但完全不相邻的代码块** → Git 自动合并，无冲突
  例：你改第 10 行，同事改第 50 行，中间隔很远，Git 可以自动拼接。

## 5. 冲突长什么样

```
<<<<<<< HEAD   // 当前分支（你现在所在分支）
String name = "张三同学";
=======        // 分割线
String name = "小张三";
>>>>>>> feature // 要合并过来的分支
```

你需要删掉标记 `<<<<<<` `=====` `>>>>>>`，手动保留正确代码，然后 add、commit。

## 一句话总结

>
> 冲突 ≠ 一定改同一行；
> 冲突的本质：**两个分支对同一个文件的同一段连续上下文，做了无法自动兼容的变更**。
